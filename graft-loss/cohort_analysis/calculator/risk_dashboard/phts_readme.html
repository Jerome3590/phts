Overview

The PHTS (Pediatric Heart Transplant Survival) Risk Calculator uses a single model trained only on the top 15 high-importance/causal features from SHAP/FFA analysis. The Combined cohort (all primary diagnoses) is used; the model is saved to Combined_top/. Risk prediction and causal analysis use this model only.

Model

The calculator uses one model:

  • Top-features model: Trained on the top 15 high causal/importance features only. Output: outputs/models/Combined_top/. Train with python train_python_models.py --top_features_only. The full pipeline (training → SHAP/FFA → deployment) is in End-to-End Workflow.

Clinical Features

The calculator uses modifiable clinical features that can be influenced by clinical intervention:

  • Kidney Function: eGFR, BUN, Creatinine
  • Liver Function: AST, ALT, Bilirubin
  • Nutrition: Albumin, Pre-albumin, Total Protein, BMI
  • Cardiac Support: LVAD, ECMO, MCSD
  • Respiratory: Ventilation, Tracheostomy
  • Immunology: PRA, HLA pre-sensitization
  • Demographics: Age, Height, Weight
Note: The calculator focuses on modifiable features that clinicians can influence through intervention, rather than fixed demographic or diagnostic variables.

Dashboard Tabs

The risk calculator has three tabs:

  • Risk Calculator: Enter clinical features and get risk score and top causal factors from the top-features model (Combined_top/).
  • Causal Analysis: View importance and causal responsibility charts; adjust top causal factor values and see risk update in real time.
  • Documentation: This guide.

End-to-End Workflow

The calculator is produced by the following pipeline (run via the calculator workflow notebook or scripts):

  1. Train top-features model: python train_python_models.py --top_features_only. Trains CatBoost, XGBoost, and XGBoost RF on the top 15 high causal/importance features only. MC-CV selects best model by C-index (then AU-PRC). Output to outputs/models/Combined_top/. Optional: --top_features_file path/to.csv for a custom feature list.
  2. SHAP/FFA: Run SHAP/FFA for Combined_top (e.g. run_shap_ffa_workflow.py with --model-variant top or equivalent). Writes dashboard_data.json and top_causal_factors.csv to outputs/shap_ffa/Combined_top/.
  3. Deploy: Package models and dashboard data for the risk calculator. prepare_lambda_dir_phts.py copies only Combined_top/ into the Lambda directory; the dashboard and API use this single model.

SHAP values: if the best model is XGBoost, only XGBoost SHAP is used; if the best model is CatBoost, SHAP is combined from CatBoost and XGBoost with weights derived from C-index. Rules are always extracted from the XGBoost JSON for the model.

Models and Results

Model Types

Three survival model types are trained (top 15 features only):

  1. CatBoost-Cox: Gradient boosting with native categorical support
  2. XGBoost-Cox: Extreme gradient boosting for survival analysis
  3. XGBoost-Cox RF: XGBoost with random forest base learners

The best-performing model is selected and deployed (see below).

Best Model Selection

Selection uses Monte Carlo cross-validation (MC-CV):

  • Primary metric: Mean C-index (Concordance Index) across MC-CV splits
  • Tiebreaker: Mean AU-PRC (Average Precision) when two or more models tie on C-index

The chosen model is written to best_model.txt in outputs/models/Combined_top/. The dashboard loads and uses only this best model (no ensemble).

Model Performance Metrics (MC-CV)

During training, each model is evaluated with the following metrics (reported per split and aggregated):

Metric Description
C-index Concordance index for survival (primary selection metric). Mean ± SD and 95% CI across splits.
AU-PRC Area under the precision-recall curve (tiebreaker for selection).
AUC Area under the ROC curve at the evaluation time horizon (e.g. 1 year).
Recall Recall at the evaluation time horizon.

Exact values for the deployed run are stored in best_model.txt and in the training logs (e.g. MC-CV mean C-index and AU-PRC per model).

C-Index Interpretation

The C-index (Concordance Index) measures the model's ability to correctly rank patients by risk:

  • C-index = 0.5: Random guessing (no predictive ability)
  • C-index = 1.0: Perfect prediction
  • C-index > 0.7: Good discrimination
  • C-index > 0.6: Moderate discrimination
  • C-index < 0.6: Poor discrimination

Our Models: Selection targets the highest C-index (and AU-PRC when tied); typical deployed models achieve moderate to good discrimination (C-index often in the 0.56–0.67 range depending on run).

Risk Score Calculation

The calculator uses only the best model from Combined_top:

  1. Load Best Model: The best-performing model is loaded from best_model.txt in Combined_top/
  2. Prepare Features: User-provided clinical features are converted to the model’s feature vector
  3. Predict: The model outputs a raw risk score
  4. Normalize: Raw score is converted to percentile (0–100) using the training distribution

Risk Score Normalization

Raw risk scores are on model-specific scales. The calculator normalizes risk scores to percentiles (0–100) using the training distribution:

  • Percentile 0-100: Represents where the patient's risk falls relative to the training population
  • Percentile 50 = Median risk (50% of patients have lower risk)
  • Percentile 75 = 75th percentile (75% of patients have lower risk)
  • Percentile 90 = 90th percentile (90% of patients have lower risk)

Risk Bands

  • Low Risk: < 25th percentile
  • Medium Risk: 25th-75th percentile
  • High Risk: 75th-90th percentile
  • Very High Risk: ≥ 90th percentile

Model Training

Training uses:

  • Data: Combined cohort; temporal split (e.g. 80% train / 20% test by transplant year) for evaluation; MC-CV over multiple splits for model selection
  • Feature engineering: Top 15 causal/importance features prepared and standardized
  • Evaluation: C-index (primary), AU-PRC (tiebreaker), AUC and Recall at a fixed time horizon; best model written to best_model.txt

Causal Analysis

Overview

The Causal Analysis feature provides an interactive interface for exploring how causal factors affect patient risk in real-time. This allows clinicians and researchers to:

  • Visualize the importance and causal responsibility of top factors
  • Experiment with different factor values to see their impact on risk
  • Understand which factors have the greatest influence on graft loss risk

What is Causal Analysis?

Causal analysis identifies which clinical features have causal responsibility for graft loss risk. The pipeline:

  1. Rules: Extracted from the XGBoost JSON model; applied to the temporal test set to count rule firings per feature
  2. SHAP: Computed on the test set (XGBoost only if XGBoost is best; otherwise combined CatBoost + XGBoost with C-index–based weights)
  3. Causal responsibility: (rule firings / total firings) × SHAP importance, then normalized for the top factors used in the dashboard

Causal Responsibility Calculation

For each feature, causal responsibility is computed as:

causal_responsibility = (rule_frequency / total_rule_firings) × SHAP_importance

Where:

  • rule_frequency: Count of rule firings involving that feature on the test set (rules are applied to test-set instances)
  • total_rule_firings: Total rule firings on the test set
  • SHAP_importance: Per-feature importance from SHAP values computed on the test set (XGBoost only if XGBoost is best model; otherwise combined CatBoost + XGBoost with C-index–based weights)

Rules are always extracted from the XGBoost JSON model. SHAP and rule application use the temporal test set only, to avoid overfitting and match evaluation methodology.

Why Causal Analysis Matters

  • Clinical Interpretability: Identifies which features clinicians can actually modify to affect outcomes
  • Intervention Guidance: Shows which interventions might reduce graft loss risk
  • Feature Prioritization: Ranks features by causal impact, not just correlation
  • Model Transparency: Provides explainable AI for clinical decision-making

Features

1. Visualizations

  • Importance Chart: Bar chart showing the top 10 causal factors by importance score
  • Causal Responsibility Chart: Bar chart showing causal responsibility scores (0-1 scale)

2. Interactive Controls

The dashboard provides interactive controls for the top 15 causal factors:

  • Numeric Features: Range slider and number input for easy adjustment
  • Binary Features: Dropdown menu (Yes/No or 0/1)

3. Real-Time Risk Recalculation

When you adjust any causal factor:

  1. The dashboard automatically calls the /risk API endpoint
  2. Risk is recalculated with the updated feature values
  3. Results update immediately without page refresh
  4. Risk comparison panel shows the impact of changes

4. Risk Comparison Panel

Shows three key metrics:

  • Reference Risk: Risk score calculated from current form values (or default values)
  • Current Risk: Risk score after modifying causal factors
  • Risk Change: Absolute difference and percentage change, color-coded (Green = decrease, Red = increase)

Causal Factor Metrics

Importance Score

  • Combined importance from multiple sources (SHAP, FFA, model-based)
  • Higher values indicate greater influence on risk prediction
  • Normalized across all factors

Causal Responsibility

  • Measures causal contribution to the outcome
  • Range: 0.0 to 1.0
  • Values closer to 1.0 indicate stronger causal relationships
  • Based on counterfactual analysis

SHAP Importance

  • SHapley Additive exPlanations importance
  • Measures average marginal contribution across all feature combinations
  • Provides model-agnostic feature importance

Best Practices

  1. Start with default values: Use default values to establish a reference point
  2. Adjust One Factor at a Time: Isolate the impact of individual factors
  3. Compare Scenarios: Use the comparison panel to see how interventions might affect risk
  4. Consider Clinical Context: Factor values should be clinically realistic
  5. Review Multiple Factors: Some factors may interact, so consider combinations

Limitations

  • Top 15 Factors Only: Controls are provided for top 15 factors; all factors are shown in charts
  • Real-Time Calculation: Each adjustment triggers an API call; rapid changes may cause delays
  • Feature Availability: Not all causal factors may have corresponding form inputs
  • Model Limitations: Risk predictions are based on trained models and may not capture all clinical scenarios
